# F.022 — Game 2: Toy Story Sequencing + Routine Anchors

**Tier 3 — cut first, without discussion** · Owner: **P1** · Reviewer: P3 · Status: Not started

## What
2–4 crops form a routine from the child's own objects and their **real** daily
routine. Model it, act it out with the real toy off-screen, then order it.

## Depends on / Blocks
Depends on F.008, F.009, F.016. Blocks nothing.

> **Only start this if Tier 2 is done and tested** (§16.1).

## Done when
- **Routine anchors** captured first: two of bath time, bedtime, snack, getting
  dressed, going out (§6.2 Layer 3). These become the sequence templates, so
  sequences are the child's *real* routine.
- Loop: model it (twice, identically, for sameness profiles) → **"Do it with the
  real {companion}!"** off-screen → scramble → child taps in order → playback
  → **save as a printable visual schedule**.
- **Step 3 is where the learning happens; the screen is only the score** (§8.2).
- **Tap-to-place is default.** Drag works if attempted but is never required —
  sustained-contact dragging is genuinely hard with fine-motor differences.
- Wrong tap → silence, crop springs gently back, nothing marked. Second wrong →
  only the correct next crop stays tappable.
- The saved strip is a real clinical artefact — a visual schedule — not just a
  game outcome (§8.2).
- Phone: vertical strip, top to bottom (§4.3).

## Review checklist
- [ ] Does the sequence use the child's **real** routine, not an invented one?
- [ ] Is tap-to-place fully sufficient, with drag never required?
- [ ] Wrong tap: silent spring-back, nothing marked?
- [ ] Does the act-it-out step actually appear, or did it get skipped as
      "not code"? It's the point of the game.
- [ ] Is the saved schedule printable?
- [ ] Thin layer, no engine logic duplicated?

## Not in this file
No narrative generation beyond short routine steps. No model call at runtime —
templates and slots only (§8.2).
